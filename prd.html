PRD · Ohalo Living Factory · Scenario A · Logistics Automation
The Facility Orchestrator
Real-time dispatch engine that automates cart movement using biological deadlines and keeps every digital pollination record perfectly in sync with its physical plant.
The Problem
  • 33% of skilled technician time is logistics (prepping / moving carts). Not pollination.
  • Priority plants have a 48-hour viability window. A cart in the wrong aisle misses the deadline and can't be used.
  • No system currently tracks cart location, biological age, or station readiness in real time.
  • Potentially logistical issues like technicians waiting for carts; carts wait untracked in aisles (reducing throughput).
Why Scenario A First
  • Less the capex of workstation robotics with greater annual savings ($3.46M/yr).
  • ~1 year payback. Net $4.45M/yr after opex.
  • Decouples labor from elapsed time: technicians start the next session while the cart is still in transit.
  • Builds the movement data layer.

Core Features
Phase 1
Biological Priority Queue (BPQ) Core Feature Software
  • Ranks every cart in the warehouse using FEFO (First Expiring, First Out) combined with travel distance, station readiness, and batch cross-compatibility.
  • Recomputes priority scores every 60 seconds across all carts and automatically issues move tasks to shuttle robots and conveyors, or operators.
  • Soon-expiring plants are always staged nearest to pollination cells (priority zone), delivered just-in-time to available technicians.
Ranking Inputs
  • Within 48 hour window? + Time remaining on 48-hrs
  • Station readiness: technician available + cell clear
  • Travel distance to nearest ready pollination cell
  • Batch compatibility: pollen donor match for the cross
Dispatch Outputs
  • Shuttle move task: cart ID, origin slot, destination cell
  • Conveyor lane assignment for transfer segments
  • Technician HMI alerts: "next cart arriving in N min", etc
  • Supervisor alert if no safe dispatch path exists within window
Design interface: Operators would see a list of HOT items (less than 5 hrs left in window), followed by priority items (within window but not urgent), ranked by the above logic.
Bits-to-Atoms Sync · Digital Cross Record Core Feature Software
  • Every cart receives a persistent UUID at propagation / receiving - linked to all relevant plant data - carried by RFID tags through the entire facility.
  • Every physical transition triggers a (software) event. The digital record is always in sync with the physical plant (assuming the plants stay in their carts).
Physical Event Trigger Software Action
Warehouse Intake Cart scanned into facility Creates CartID · starts biological clock · assigns storage zone
Storage Slotting RFID read at storage rack Confirms location · BPQ calculates dispatch priority
Cart Dispatch BPQ issues move task State → IN_TRANSIT · AMR assigned · ETA updated at destination cell
Pollination Cell Arrival RFID read at pollination cell State → STAGED · technician notified · delivery logged
Pollination Complete Technician confirms cross + pollen scan Records pollen lot + technician ID · state → COMPLETED
Post-Poll Transfer AMR pickup at completed cell Routes cart to recovery zone · closes biological timer
Hardware Layer

All hardware directed via REST/MQTT — no vendor lock-in.

  • Shuttle Robots (≥2): cart retrieval and cell delivery. 3–5 min cycle. Having a pair ensures no single failure point.
  • Conveyor lanes: storage rails / racks and transfer lanes for faster movement / reconfig.
  • RFID readers: at rack entries, conveyor merge points, cell gates, etc. Events trigger when RFIDs cross readers.
  • Workstation HMIs: optimized UI for priority visibility, dispatch, pollination and completion.
  • Facility dashboard: live WIP, BPQ queue, deadline risk, robot status, shift throughput vs target.
