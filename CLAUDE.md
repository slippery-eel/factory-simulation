A browser-based system-dynamics simulation for the Ohalo "Living Factory" seed production case study. No build step, no dependencies — open the HTML files directly in a browser (or via a local server for cross-file features).

## Architecture: simulation.html

The entire simulation lives in a single HTML file. Code is organized into clearly labeled sections (using `═══` banner comments):

1. **CSS** — inline styles only; dark theme (`#0f172a` base)
2. **SVG diagram** (`id="diagram"`) — static markup for 4 stocks, flow paths, labels; particles generated by JS only
3. **`STOCKS_GEO`** array — pixel geometry constants (fillX, fillW, fillBottom, fillHeight, cx) mirroring each stock's SVG rect; used by `renderFrame()` to compute fill heights
4. **Constants** — `BUFFER_CAP=800`, `POLL_CAP=50`, `PRIORITY_RATIO=0.2`, `DEADLINE_HRS=48`, `WARN_HRS=40`, `TARGET_WEEKLY=500`
5. **`params`** object — user-adjustable + derived parameters. Survives resets. Rates stored internally as **k plants / sim-hr**. Derived fields (numWorkers, totalFlowTimeHrs, stationCap) are recomputed by `syncAll()`.
6. **`freshState()`** — returns a new clean `sim` object. Contains stocks (`bufReg`, `bufPri`, `poll`, `postPoll`), flows, elapsed clock, failure counter, particles array, spawn accumulators, and `priorityCohorts`.
7. **`dom`** object — all `getElementById` calls in one place. Add new refs here before touching the DOM anywhere else.
8. **`isShiftActive()`** — pure function; returns bool based on `sim.elapsed` and schedule params. No side effects.
9. **`updateSimulation(wallDt)`** — all simulation math; zero DOM writes. Uses `simDtHrs = wallDt * params.simSpeed / 5`.
10. **`spawnParticle()` / `removeParticle()` / `clearAllParticles()`** — particle lifecycle helpers.
11. **`renderFrame()`** — all DOM/SVG writes; zero simulation math. Reads `sim` and `params`, writes to `dom.*`. Calls `renderChart()` at end.
12. **`renderChart()`** — canvas throughput chart; 24-hour and 7-day rolling averages of F3.
13. **`tick(timestamp)`** — RAF loop; calls `updateSimulation` then `renderFrame`; caps `wallDt` at 50ms; guarded by `document.visibilitychange`.
14. **`syncAll()`** — reads all control inputs, derives all `params` fields, updates display labels. Called by every input's event listener and once on load.
15. **Controls section** — event listeners wired to `syncAll()`.
16. **Save / Restore** — `saveState()` / `restoreState()` snapshot `params` and schedule inputs to `localStorage` under key `'lf-sim-save'`. Restore button is enabled on load if a save exists.

## Critical Invariants

**Time scaling:** `simSpeed` = sim-hours per 5 real-seconds. Default 8 → one 8-hour shift in 5 real seconds. All stock math uses `simDtHrs`; particle visual movement uses `wallDt` directly so particles always look smooth.

**Unit system:** 1 sim unit = 1,000 plants (k plants). Flow rates in **k plants / sim-hr** internally. F1/F3 UI inputs accept **k plants / week**; `syncAll()` converts to k/hr before storing in `params`.

**Session model (F2/F3):** F2 dispatches plants from the buffer into worker slots (each slot holds `plantsPerSessionK` k-plants). Each in-flight batch completes at `elapsed + totalFlowTimeHrs`. F3 drains completed batches — **F3 is not shift-gated**; batches dispatched near shift-end complete after the shift closes.

**Shift gating:** `isShiftActive()` gates F1 (inflow) and F2 (dispatch). Working days = first `daysPerWeek` days of each 168-sim-hr week; active hours = first `shiftsPerDay × hoursPerShift` hours of each working day. F3 and biological aging run continuously.

**Priority routing — per-cohort deadlines:** Priority plants accumulate in `sim.priArrivalAccum`. When it crosses 1 k-plant, a new cohort `{ amount, deadline: elapsed + 48 }` is pushed to `sim.priorityCohorts`. Each tick: cohorts are sorted by deadline ascending (most urgent first); F2 drains the earliest-deadline cohort first. `sim.prAge` is derived from the oldest surviving cohort's arrival time. On deadline expiry, that cohort's remaining amount is added to `sim.deadlineFailures`. This replaces the old global `prAge` reset pattern — do not revert to that.

**Spawn accumulators:** Particles spawn when the accumulator (k plants) exceeds 1. One particle = 1,000 plants. Accumulators use `simDtHrs` so particle density reflects biological throughput, not wall time.

## Key Formulas

```
simDtHrs        = wallDt * params.simSpeed / 5
hoursPerWeek    = daysPerWeek × shiftsPerDay × hoursPerShift
f1Rate          = TARGET_WEEKLY / hoursPerWeek              (k/hr)
sessionsPerWeek = TARGET_WEEKLY / plantsPerSessionK
numWorkers      = ⌈ totalFlowTimeHrs × sessionsPerWeek / hoursPerWeek ⌉
stationCap      = numWorkers × plantsPerSessionK / totalFlowTimeHrs    (k/hr)
maxActiveWIP    = numWorkers × plantsPerSessionK                        (k plants)
```

Default steady-state: 5d × 2s × 8h = 80 hrs/week → f1Rate = 6.25 k/hr; flowTime = 0.75 hr; numWorkers = 94; stationCap ≈ 6.27 k/hr.

## Architecture: opportunity-analysis.html

Single `recalc()` function reads all inputs, computes all derived values, writes all output cells. Wired to every input's `input` event and called once on load. No simulation loop.

Key internal functions (all inside the script block):
- `recalc()` — master calculation function
- `renderGantt()` — SVG session-timeline Gantt chart
- `renderCashFlow()` — SVG 5-year cumulative cash flow chart
- `updateDecision()` — populates the weighted decision framework grid

When adding a new derived output: compute in `recalc()`, write with `setBase()` / `setScenario()` / `setSavings()` helpers.

## Architecture: layout.html

Single script block; no simulation loop. Key pieces:
- **`(function buildRacks())`** IIFE — runs once at init; generates SVG `<rect>` elements for the 6 regular bench rows and 2 priority rows into `<g id="rack-grid">` and `<g id="priority-racks">`. Runs immediately (not inside DOMContentLoaded).
- **`state`** object — `{ mode: 'g2p' | 'manual' }` for the mode toggle.
- **Event listeners** — `#btn-manual` and `#btn-g2p` toggle `manual-paths` visibility and mode state.

The SVG uses a 2D-shuttle storage layout: C-RAIL intake rail (top), dispatch rail (bottom), 7 vertical shuttle tracks, amber dashed separator between regular rows (1–6) and priority rows (7–8).

`#travel-reduction` element does **not** exist — do not reference it in JS.

## Adding New Features

- **New control input (simulation):** Add HTML, add `dom.xyzInput` ref, add event listener calling `syncAll()`.
- **New data panel card (simulation):** Add HTML card, add `dom.dpXyz` ref, write to it in `renderFrame()` only — never in `updateSimulation()`.
- **New SVG element (simulation):** Give it an `id`, add to `dom`, update in `renderFrame()`.
- **New simulation logic:** Only touch `updateSimulation()`. Never read `sim` in `renderFrame()` for math.
- **New ROI output:** Compute in `recalc()`, display with the existing `setBase()`/`setScenario()` helpers.
- **New layout SVG zone:** Add static SVG markup; if JS-driven, add to the `buildRacks`-style IIFE pattern.
